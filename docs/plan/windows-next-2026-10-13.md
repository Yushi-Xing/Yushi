# Windows 下一轮优化与上游同步评估

检查日期：2026-10-13。目标仍为 Win10 / Win11 上准确、稳定、轻量的中文输入，以及按需英语句译。按用户最近的决定保留双拼，优先全拼体验；删除其他平台源码本身不等于缩小 Windows 安装包。

- [x] 引入第一批独立修复，逐项做对应 Core/数据/配置回归；本机复跑 100 条文章探针，Windows 完整固定集由预览 Actions 执行。

这一阶段不承诺提高整句首选；它的验收是正确传递按键、可靠恢复、候选可见、旧协议可识别且不把正文写回运行日志。

### B：从失败路径改进整句纠错和排序

已保存 [第一组诊断](../notes/windows-sentence-diagnosis-2026-10-13.md)：单词“词库”“收纳”可以首选，完整正确拼音的目标句却不在输出候选；内部词图、路径分数与具体裁剪位置仍待跟踪。

- [ ] 对 `cikushounaleduoshaoci` 与错键 `cekushounaleduoshaoci` 分别记录切分、词图、候选路径及分数，先判断目标是否生成，再判断为何被压低。
- [ ] 将多处漏键、邻键、换位纠错纳入同一候选路径搜索，设置编辑预算、候选上限和时间上限；避免逐音节各自纠错后组合爆炸。
- [ ] 对合法音节误写如 ce/ci 用整句语境评分；保留“测”“册”等本来正确的反例、姓名、品牌、英文和全拼/简拼混输，限制误纠。
- [ ] 建立原始输入保留、Enter 原样输出、用户拒绝纠正及学习/撤销的一致行为；用户导航候选后迟到模型不得改顺序。
- [ ] 建立 librime 的同题离线对照，先按可再分发许可选择评测材料；不把 GPL 雾凇资源带入产品包。分别比较无模型、本地模型和 librime，模型与云翻译状态显式记录。
- [ ] 用固定训练/开发集调参；另冻结未参与调参的新文章与口语句留出集，记录完整失败，禁止把测试整句作为短语灌入词库。

建议第一阶段门槛：正常整句首选相对基线提高至少 10 个百分点，旧成功项没有未经解释的回退，纠错收益必须伴随误纠率报告。该数值是目标，不是已达到的结果；后续以新留出集确认是否泛化。分别报告 Top-1、Top-5、字符错误率、误纠率与逐键/稳定候选 P50/P95，不混用词条覆盖率。

### C：补常用词与控制模型功耗

- [ ] 优先吸收上游常用词、正确多音字和噪声清理增量，保留我们的 19,662 条补充词来源和权重；生僻字数据另测并评估是否默认提供。
- [ ] 比较 data-v3+补库、选择性新增词条与 data-v7 的准确度、包体和加载内存，更新时校验整包哈希与许可，不手改 data.lock。
- [ ] 本地模型按同一输入状态最多计算一次，设置结果过期、长度/路径/推理上限，失焦/上屏后清理；不得因 Poll 或 UI 重绘反复推理。
- [ ] 无模型、模型重排、模型补句分别测收益；无明显收益的运行方式不作为默认必需项。
- [ ] Actions 保留停键零新增推理探针；用户笔记本插电下另做短时实际验收，记录 CPU 和推理次数，出现异响立即停用该对照。CI 的 0 ms 进程 CPU 不是实际笔记本噪声证明。

### D：降低安装包体积

- [ ] 先从 Actions 产物生成文件级清单，区分下载包大小和安装展开大小；分组统计设置程序/运行时、词库、模型、释义表与 DLL。
- [ ] 单独原型验证 Win32 轻量设置，保留必需配置页、键盘导航、DPI 与辅助功能；再与 WinUI 自包含设置做同功能包体对照。
- [ ] 评估核心输入包与可选模型/领域/学习数据包；如采用可选下载，需要锁定来源、校验哈希、断网回退，并保证默认输入能力完整。
- [ ] 保留 x64 与 x86 TSF，不以删 32 位兼容降低体积。双拼维持现状，避免为很小的体积收益承担配置迁移风险。

Win32 的收益须以同一压缩设置、同一词库与模型实测；在测量前不承诺能把安装包降至某个大小。

### E：独立的英语候选句翻译

- [ ] 仅在显式操作后翻译当前高亮整句；普通打字无云请求，普通选词仍输出中文。
- [ ] 翻译与输入状态独立，以会话、候选身份及文本版本绑定结果；换句、上屏、换焦点、关开关、进入私密状态时取消。
- [ ] 缓存有条数/字节上限，支持超时、限流、坏 JSON/流、重试退避和在途取消；密钥用 Windows 安全存储。
- [ ] 不直接同步“自动带光标前文发云联想”的改动，用户当前要求是按需翻译候选句，需要独立的数据发送范围。

## Windows 验收矩阵与发布门槛

验收顺序按用户指定：基础 Windows 输入框 → 浏览器 → VS Code → 微信。Win10 22H2 和 Win11 分开记录，Win11 同时记录实际构建号；32 位宿主另测。

| 维度 | 必测内容 |
| --- | --- |
| 基础控件 | Edit、RichEdit、记事本；空/已有文字/选区、多行、输入中间编辑、分段上屏。 |
| 浏览器 | Edge/Chrome 的 input、textarea、contenteditable、密码；记录实际 InputScope，不把 InPrivate 自动等同于 private 标记。 |
| VS Code | 编辑器、搜索、终端；单键英文直通、Tab、方向键、Ctrl/Alt/Win/AltGr、焦点变化。 |
| 微信 | 聊天、搜索、多行、发送键、窗口切换；记录版本与位数。 |
| 系统搜索 | 任务栏搜索与开始菜单搜索；候选完整可见、可选、可翻页、关闭不残留、不抢焦点；SearchHost / SearchApp。 |
| 屏幕 | 100/125/150/200% DPI、不同缩放多屏、合法负坐标、边缘、上下放置、字号变化。 |
| 生命周期 | Server 失败/慢启动/崩溃/恢复、睡眠唤醒、断线、旧 DLL 留在未重启应用、升级与回退。 |
| 安全隐私 | 跨账户/会话管道正反例、AppContainer/低完整性正例、密码与私密切换、云待发/在途取消、诊断无正文与密钥。 |
| 输入正确性 | 正常全拼、混合简拼、多处错误、合法音节错拼、英文/数字/路径/姓名反例、数字 Test/KeyDown 不重放、翻页边界。 |

IPC 的 Everyone/应用容器广泛授权仍在当前源码中，需单列身份、服务端验证与资源限额修复。第一轮已去除逐键正文运行日志并修复会话隔离/诊断导出等，不应把原始审计中的所有条目都描述成仍未修复；仍需检查日志目录 ACL、默认 InputLog 策略和历史日志处理。收窄 IPC 时必须保留合法 SearchHost/AppContainer 接入，不能简单删除授权导致兼容倒退。

各批次遵循：小分支 → 对应回归 → 固定准确度/停键功耗检查 → Windows Actions 构建 → 附件哈希与版本核验 → 安装验收。只有 CI 证据的项目标注“待真机”，不勾选真实宿主验收。

## RIMES 参考项目的近期更新
