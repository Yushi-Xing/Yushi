# Windows 专用输入法重构范围

2026-10-04，根据本次产品要求和当前源码制定。本文是目标规格与实施顺序，不表示功能、删减或兼容性修复已经完成。

## 产品目标与已确认选择

专注 Windows 10 / Windows 11 日常输入：首先把中文打得准确、顺畅，再用不打扰输入的英语译词与句子翻译帮助学习。

用户已确认：

- 第一版只保留全拼；自有双拼方案以后再制定，不擅自选用或改名包装其他双拼方案。
- 高亮整句停留或主动请求时按需云翻译，第一版目标语言为英语。
- 不再维护 macOS / Linux 产品，不追求五笔、注音、多种双拼等输入方案大全。
- 准确率与宿主兼容性优先于附加功能和界面装饰。

当前安装器最低版本为 Windows 10 1809、面向 x64 兼容系统，并带 x64 / x86 两份 TSF DLL。重构保持这个已声明的最低版本，主要验收 Windows 10 22H2、LTSC 2019 / 2021 与 Windows 11。它是测试目标，不是新版本已通过的结论。32 位应用的兼容必须保留；32 位 Windows 操作系统和 ARM64 原生支持不由“两份 DLL”自动获得，另行确定与验证。

## 功能取舍

| 范围 | 第一版目标 | 原因 |
|---|---|---|
| 中文输入 | 全拼、简拼及混用、整句转换、分段选词、拼音光标编辑 | 输入主体 |
| 自动拼音纠正 | 本地处理多键、少键、错键、换位及上下文歧义；保留原始输入 | 提高准确率，不依赖网络 |
| 个人学习 | 词频、选择偏好、词序、用户词、个人敲错及撤销学习 | 输入越用越贴合用户 |
| 中英混输 | 常用英文词、专名、数字标识符和句末英文；英文模式可纯直通 | 文档、代码和聊天日常需要 |
| 词库 | 基础词库、常用短语、精选技术词；领域词库改为按需安装 | 不为缩小体积删除日常高频词 |
| 英语译词 | 小型高频词释义、简短词性提示、显式输出译词 | 保留轻量学习属性 |
| 候选整句翻译 | 当前高亮完整句子的英语译文；按需联网 | 用户指定的新功能 |
| 本地模型 | 优先保留一份对准确率有实证收益的模型；备用模型改为可选 | 准确率优先，避免双模型重复随包 |
| 候选界面 | 简洁布局、页码、高亮、纠错提示、译文辅助行，适配 DPI | 先保证可用与可读 |
| 设置 | 输入、外观、英语学习、数据与隐私、关于五页 | 减少设置负担 |
| 维护 | 明确的升级、卸载、配置迁移、用户数据保留与恢复 | 重构不损失已有习惯数据 |
| 开发验证 | 保留 CLI、冻结评测集、日志回放、数据打包与安全测试 | 给准确率和性能提供可比较的依据 |

第一版产品移除：macOS / Linux 平台壳及其安装发布链、多套双拼、大千注音、五笔、辅码与码表界面、日语与西班牙语释义及等级表、问字与通用问答、云端中文联想与续写、复杂词汇等级统计、装饰性悬浮状态条和多种渲染实现并存。

低优先项：计算器、中文金额、Unicode 码点等前缀模式不纳入首版；日期时间和 emoji 可在不影响按键规则、体积很小时保留，不能以这些小功能数量代替包体积优化。繁体输出、自定义短语和任意第三方词库导入不扩大首版范围，迁移时保留旧数据文件而不销毁。

“移除”包含产品入口、运行时逻辑、随包数据、安装器、配置、测试、文档与 CI 的一致清理，不能只隐藏设置项。基线评测和必要数据生成工具不随用户可见功能一起删除。

## 自动纠错的实际行为

已有全拼纠错、整句噪声信道和个人敲错学习，应以它们为基础改进，而不是重写前先丢掉现有收益。

1. 用户敲的字符串保持原样，纠正用于候选解码。拼音行可提示纠正，但不能静默篡改原始按键。
2. 明显换位、多键、少键或错键给出纠正后的候选，例如 `mingtain` → 明天、`woxiagnqu` → 我想去。
3. 对合法但含歧义的拼音，结合整句与个人习惯排序；低置信度时保留原读法，不强行改成另一句话。
4. 合法简拼、英文词、专名、标识符与数字不是噪声，不能因“像错拼音”而强行纠正。
5. 已开始导航或选词时，不因迟到的模型结果改变所选位置；Enter 原样输出的语义保留。
6. 正确接受和拒绝、退格重打都作为评测与学习信号；进入隐私输入后不新增个人记录。

验收同时看首选命中率、字准确率、误纠率、错误恢复率、重打次数和逐键延迟。以固定的普通输入、简拼、真实错拼与英文标识符集比较；只看错拼案例容易让“什么都纠正”的实现看起来很好。

性能先建立当前版本基线，再给相同设备上的热路径 p95 / p99 和长句最坏值定门槛；不把少量样例的平均耗时写成兼容所有机器的保证。

## 候选句子翻译

当前 `Engine::annotate` 主要查询本地词级释义，长句通常没有完整译文。已有“翻译应用选区”会进入替换选区的评审状态；它不能直接替代“正在组句的候选旁显示译文”。

目标交互：

```text
拼音：woxiangbajutidaimaquedingxia
1 我想把具体代码确定下
  I'd like to finalize the specific code.
2 我想把具体代码确定一下
```

示例仅说明布局，不作为真实翻译质量基准。中文候选先出现，译文异步补充。普通空格、数字选词始终输出中文；只有明确的“输出译文”动作输出英语。

- 第一版只翻当前高亮的完整句子，包括词图整句和本地模型生成的整句，不逐键翻全页。
- 英语学习的云翻译独立开关，默认关闭；填写服务地址、模型、密钥后，明确启用才联网。关闭中文云联想不能把英语翻译一起关闭，启用英语翻译也不能恢复被移除的云续写。
- 高亮稳定约 500 ms 后发起请求，或通过显式操作立即请求。此数值是初始设计参数，验收后调整。
- 请求只携带所选中文句子和目标语言；不读整个文档，不发原始按键、候选全集、应用名或额外上下文。
- 以可信连接、上下文、组句版本和候选文本绑定请求。继续打字、导航、换焦点、结束组句或进入隐私模式时取消；返回结果必须重新检查关联，不可给新的候选贴上旧译文。
- 必須实际取消待发送与在途请求，不只丢弃返回结果。进入隐私模式前已经发出的数据无法撤回，因此隐私确认必须先于请求创建。
- 新输入上下文尚未确认隐私属性时不联网、不记录输入；密码 / PIN / keyboard-disabled 不启用该功能，private 输入不翻译。
- 失败、离线和限流只让译文留空，不阻塞候选、编辑或上屏，不弹窗干扰。
- 缓存默认只在内存，按文本、目标语言、提供商和模型区分，设数量与字节上限；不把句子长期保存为学习资料。
- 设置响应体积、请求频率、并发数和超时上限；API 密钥独立受保护保存，诊断导出始终脱敏。
- 词译与句译各保留单一目标语言，不把整句当词典词条计入 CEFR 词汇数。

实现时翻译业务和异步关联状态归 Core / 专用翻译组件，Windows 适配层只传事件和展示结果；保留现有 Core 与平台隔离约束。新增帧字段应兼容旧客户端；无法服务的协议版本要明确拒绝并安全退回，不能仅日志告警后继续接受。

## Windows 兼容性必须具体落到这些场景

| 场景 | 验收重点 |
|---|---|
| Win10 / Win11 冷启动 | 设置可打开，首次启动不缺依赖；PE 导入不强依赖 Win11 独有 API |
| 64 位与 32 位宿主 | 两种 TSF DLL 同步构建、注册、版本与协议一致；覆盖 WPS、Office 和聊天软件的实际位数 |
| 标准 Win32 与现代文本框 | 记事本、Word、WPS、Edge、Chrome 的组句、光标、选词与失焦提交 |
| Electron / Chromium 与终端 | VS Code、Windows Terminal、实际使用的聊天软件；避免吞 Tab、重复字符、丢标点 |
| 系统 UI / AppContainer | 搜索框、设置、打包应用中的 DLL 加载、候选可见性和必要权限 |
| 焦点与文档上下文 | 同应用多个输入框、不同应用往返；组句隔离，不能串字、串隐私状态或串译文 |
| 编辑操作 | 插入、删除、选中后替换、Esc、Enter、数字键、失焦、应用主动结束 composition |
| 键盘布局 | 美式与常用非美式布局、AltGr、组合音符；识别失败时正确交还宿主，不假定所有键位相同 |
| 显示与定位 | 100% / 125% / 150% / 200% 缩放、混合 DPI 双屏、负坐标、屏幕边缘、深浅色、高对比度 |
| 服务异常 | Server 未启动、崩溃、卡住、重连；有等待上限，未接管的按键交还应用，已接管组句妥善结束或恢复 |
| 安装与升级 | 正确注册两种 DLL；保留用户数据；旧 DLL 在未重启宿主中可安全处理，卸载清理与自启范围正确 |
| 多用户 / 权限 | 每用户、每登录会话的 IPC 隔离；AppContainer 只获必要权限，不能因追求兼容开放所有会话与日志 |

兼容某个应用需要记录应用版本、系统构建、输入控件、具体步骤和实际结果。上述是验收矩阵，不能由交叉编译或 Windows Server CI 推断每项已通过。

目前 `key_sink.rs` 在断开服务时仍会吞部分字母，`client/pipe.rs` 在 UI 线程执行同步连接与读写；这些是需要先复现再处理的明确检查点，不能只重做候选窗。

现有 Win10 设置兼容处理是自包含部署与延迟导入；仓库已经实施，不能当成新发现尚未修的同一问题。原生 Win32 设置窗口是本次建议采用的替代方案，可同时去掉 Windows App Runtime 依赖，但需要重新实现必需设置并完成可访问性、DPI 与 Win10 验收。

`uiAccess` 与候选显示路径需重新评估：不能把它当作普通置顶的无限权限开关。先验证宿主支持的 TSF 展示路径与正常完整性级别的行为，保留能工作的回退；任何保留的 uiAccess 路径都要遵守签名、安装位置和权限约束，不把安装自签根证书作为普通发行流程。

## 体积优化的事实与取舍

当前工作区没有 `data/generated`、成品安装包或打包运行时，无法实测安装包能缩小到多少 MB。

已核查的事实：

- macOS / Linux 没有装进当前 Windows Inno 安装包。删除其他平台减少仓库、依赖维护与测试负担，并不会直接去掉 Windows 包中一份并不存在的平台壳。
- 七套双拼主要是小型键位映射，删掉它们的主要收益是产品与行为复杂度，而不是几十 MB 的空间。
- 安装器 README 和 Win10 记录中的设置运行时约 56 MB / 185 个文件，是旧打包记录，未在本机重测。更换为原生 Win32 设置页后才可能去掉这一项；不能只删除运行时文件而保留依赖它的设置 exe。
- 当前 `.iss` 包含英语、日语、西班牙语与英→中释义、领域词库、笔画、五笔，以及两份可选本地模型；只保留必要英语资料、把领域词库与备用模型改为可选，才是数据瘦身主线。
- 仓库记录知微模型约 56 MB fp16，同样是文档中的历史数据，不是当前成品模型或压缩安装包实测。
- 精简模型必须与固定评测集比较；量化、裁词或删除备用模型若降低输入准确率，不能用缩小体积掩盖退步。

产物分别报告下载包体积、安装后占用、启动峰值内存和稳定运行内存。不能把源码目录体积、模型权重大小、加载内存或未压缩运行时之和称为“安装包大小”。

推荐发布结构是一个基础包：输入内核、必要词库与语言模型、两份 TSF DLL、轻量设置、精选英语释义；增强模型和领域词库作为经校验的可选包。不要发布没有正式词库、仅能打几十个样例词的所谓精简版。

## 实施顺序与验收

1. **冻结基线与保护迁移。** 保存当前全拼／简拼／纠错／混输行为评测；记录现有配置和用户数据格式；安装器和设置的实际体积清单；准备 Win10 与 Win11 的验收环境。
2. **优先处理输入和隐私边界。** 修复前轮安全审计 A1–A4；建立连接所有权、逐上下文隔离、隐私先确认、有限等待和异常回退。日志默认不写输入内容，诊断不携密钥。
3. **收拢产品与构建。** Windows 单产品，只保留全拼首版入口；移除不再需要的平台、方案和云问答；清理配置、数据清单、文档、依赖与 CI；不得删 x86 TSF 或行为评测工具。
4. **增强自动纠错。** 以误纠率和输入恢复率约束候选改进；验证无模型、普通模型与精简模型三种路径；不让云 API 成为中文输入的必需依赖。
5. **实现候选句译。** 独立英语翻译开关、异步高亮关联、取消与有界缓存、单句请求、译文展示与显式输出；测试迟到结果、切应用、换模型、隐私与离线场景。
6. **设置与包体优化。** 原生 Win32 设置界面替换重运行时；按实测收益确定单模型、精选释义和可选词库清单；完成配置迁移并保留原数据备份。
7. **真机兼容验收与发布。** 覆盖矩阵中的实际宿主；制作两种位数 DLL 的安装包；验证冷启动、升级与卸载；每项发布结论都附真实验证记录。

上一轮 Linux workspace 基线为 641 项通过、1 项性能测试忽略；这是工程基础，并不是 Windows 产品已经兼容的证明。修复细项与证据见 [2026-10-04 安全审计](../notes/security-audit-2026-10-04.md)。

本文完成的是产品范围与实施规格。真实 Windows 修复和整句翻译仍需代码实现及上述验收，不能把本文的目标功能用于宣称已经交付。
