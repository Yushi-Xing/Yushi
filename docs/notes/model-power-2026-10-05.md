# 本地模型停键持续活动排查

## 反馈与当前边界

用户安装 0.1.6-beta.3 后，在插电的笔记本上输入普通短句“由此看来没什么问题”，停键并保留拼音／候选窗时仍有约每秒四次的异响；切回微软拼音消失，关闭本地整句模型也消失。尚无这台电脑的 CPU／功耗采样，不能仅由声响判断硬件故障或确认唯一代码原因。

TSF 组句轮询为 80 ms；候选帧与位置未变已跳过重画。Windows 模型运行在 CPU 上。没有把轮询频率与用户估计的声音节律直接等同。

## 已复现的代码缺陷与修正

模型分数缓存只保留最后一个读法，同一查询比较其他读法时清空旧分数；后台结果后的重查询又触发相同计算。假模型复现：两种读法交替查询 20 轮，修正前调用 40 次，修正后调用 2 次。

改为同一输入作用域内按读法保留分数，一次提交全部读法；保留 1024 个分数槽位上限，超限回退而不清空已算的分数。输入／前文切换及会话重建换唯一查询代，旧结果丢弃。换输入、卸载模型后停止后续批次；当前单批计算不能强行中断。此缺陷已确认，不等同于用户的纯中文短句异响已解决。

## 验证

- 新增同步重复调用、异步多读法收敛、实际混输查询、分数隔离、容量上限、查询代及卸载取消回归；核心 313 项通过。
- Windows Server 增加停键后 200 次 Poll 不再次调用假模型的回归。
- `model_idle` 显式探针使用锁定产品词库、LM、英文表和随包 P2C，检查用户短句与混输输入；等待计算结束后继续 Poll 两秒，断言新增推理为零，并记录 Windows 进程 CPU 毫秒。无用户配置、学习、日志正文和网络服务。该探针已由 Windows Actions 实际执行并通过，具体结果如下。
- 本机只执行核心测试与 lint，构建并发为 2，产物在 D 盘；完整 Windows 测试与安装包在 GitHub Actions 执行。
